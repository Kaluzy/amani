# Amani website architecture

## GitHub Pages

The public project site is https://kaluzy.github.io/amani/. `deployment.js` reads
static-hosting meta tags generated by `scripts/build-pages.js`; local hosting
continues to use the Node API. The Pages build emits real entry points for every
repository/topic and exports only public GET endpoints as JSON. Links, direct
loads, search and browser history retain the `/amani` project base path.

`.github/workflows/pages.yml` refreshes public Trending data hourly, exports a
public recovery seed, builds and deploys `dist/` through GitHub Pages Actions.
The allowlisted seed contains public metadata and trusted observations with their
original timestamps, never local suggestions or the private database. A build
cache preserves accumulating public history; the latest deployed public seed
provides recovery after cache eviction. Failed refreshes fail the build and leave
the last successful deployment intact. Schedules may be delayed by GitHub.

Pages suggestions are public GitHub Issues, not a nonfunctional POST form.

The Express process serves one shared shell for the application. The browser router
owns page mounting; shared navigation, typography, responsive layout, loading/error
states and cards have one implementation. CSS, Chart.js and application modules are
served locally. No build step, CSS CDN, font CDN or chart mock is required.

## Modules

- `scripts/serve-api.js`: app factory, API validation, canonical routes and local assets.
- `src/lib/database.js`: existing schema, ID-safe metadata upserts and observations.
- `src/lib/catalog.js`: atomic completed collections, normalized repository records,
  trusted history, annual growth, data coverage and persisted suggestions.
- `scripts/scrape-trending.js`: public HTML parsing and daily/weekly/monthly collection.
  Optional existing GitHub API cache restores metadata without inventing history.
- `public/client.js`: navigation lifecycle, cancellation, mobile menu and global search.
- `public/pages.js`: page views and interactions; real local Chart.js rendering.
- `public/ui.js`: escaped components, API error handling and consistent formatting.
- `public/design.css`: layered reset/tokens/layout/components/responsive rules.
- `public/cards.css`: card readability, visible statistic labels, exact counts, full
  descriptions, period-specific gains, truthful ranking context and responsive list view.
- `scripts/qa-check.js`: read-only live API checks and optional isolated regressions,
  with bounded latest/previous JSON reports in `.trendshift/qa/`.

Legacy `.html` paths redirect to canonical application routes. Older public templates
and JS remain historical references; only shell.html and the modules above are active.

## Feature contract

| Route | Data | Behavior |
| --- | --- | --- |
| `/` | status + daily repos | overview, metrics, search, filters, sort, grid/list, pagination |
| `/daily`, `/weekly`, `/monthly` | period-specific latest completed collection | period tabs, timestamp, reload, filters, sorting, pagination |
| `/yearly` | verified first/last observations in last 365 days | observed growth, explicitly partial coverage; needs two observation dates |
| `/github-trending` | all repositories | searchable/sortable full collection |
| `/repositories/:owner/:repo` | normalized metadata, trusted history, rankings | external GitHub link, real history chart/table, topics, period links |
| `/stats` | metadata totals, languages, bucketed history | four real charts, table; no estimates for missing years |
| `/insights` | computed daily growth, star totals, creation dates, languages | navigable repository cards; no invented editorial claims |
| `/live` | latest daily collection | timestamped source-labeled feed, reload, 60s read refresh |
| `/topics` | actual repository topic metadata | topic filtering and real counts |
| `/topics/:slug` | repositories containing exact topic | shared repository listing controls |
| `/submit` | POST `/api/submissions` | validated public GitHub name, persisted pending review, duplicate handling |
| `/about`, `/privacy`, `/terms`, `/contact` | local explanatory content | working navigation with no dummy links |

All asynchronous pages have loading, empty and retry states. Unknown routes return
HTTP 404 with a navigable shell; unknown repositories return a useful error. A page
returning 200 is not evidence that it has usable data or a correct layout.

## Data integrity and provenance

`collection_runs` and `collection_entries` provide a stable batch identity. A batch
and its snapshots are inserted in one SQLite transaction; invalid rows roll back the
entire run. Readers select only the latest completed collection for each period.
Unknown metadata from HTML does not erase previously known API metadata. Failed
source requests do not overwrite an old batch. Snapshot stars/forks come from actual
page values, not a default-zero fallback after an API failure.

Existing corrupted snapshots remain for audit. Verified history includes the explicit
`github`, `trending-v3`, and `github-cache` sources; old `trending` observations are
excluded from growth/charts. Cache metadata imports do not create historical samples.
Annual views require two distinct UTC observation dates; a new database cannot claim
year-long growth. Card period gains are GitHub-reported period gains, not interpolated
history. Missing fields display as unavailable where the schema permits it.

## Running and verification

`npm run refresh` imports known cached metadata and fetches three public Trending pages.
`npm run serve` listens on localhost:3002 (PORT overrides). TRENDSHIFT_DB_PATH selects
an isolated SQLite file; default paths are relative to this repository, not shell cwd.
`npm run full` refreshes then serves. Check `/health` for served version and `/api/status`
for each period's coverage. Reload an existing process to activate backend changes.

The deployed user service is `amani-repository-hub.service`; an hourly
`amani-repository-refresh.timer` activates the bounded refresh oneshot. Both use the
existing Mise Node shim on this machine. Unit sources live in `deploy/`. Service
logs are available through the user journal. The server binds only localhost:3002;
existing access/tunnel configuration remains the source of external reachability.

`npm test` verifies transaction rollback, upsert preservation, complete-batch selection,
source parsing, cumulative totals, yearly coverage, APIs, submissions and actual browser
interactions at 390/768/1440px. Charts are real, not stubbed. Browser checks capture
screenshots and reject overflow, source injection and broken local requests.

## Ongoing QA and reporting

`npm run qa` checks the live localhost website, including source freshness, period
coverage and chart dependencies. `npm run qa:full` also executes every `test/*.test.js`
file against disposable data. `amani-repository-qa.timer` schedules this daily around
04:15 local time, with catch-up on the next active session and bounded execution.
Results are `.trendshift/qa/latest.json` and `previous.json`; failures exit nonzero
and remain visible in the user service journal. This is continuous verification,
not an unattended code-editing or external-model process.

`npm run stats` and `npm run rank` now export actual SQLite observations, never
generated history or heuristic rankings. Cache metadata restoration fills missing
fields only and cannot replace newer known totals when a source request fails.
